# Phase 2: GBA hardware abstraction on the DMG

Build with `--hal` (see `tools/hal/demos.py`). All results below are measured on
PyBoy in **DMG mode (`cgb=False`)**; nothing depends on GBC features.

## 2.1 Static I/O interceptor (`tools/hal/intercept.py`, `tools/hal/lower.py`)
* Every load/store address is resolved at compile time from proven value ranges
  (literal-pool constants, base+offset, and pointer induction `phi(C0, p+k)` bounded by
  a `cmp`+`bne/beq` against a constant). Regions: io, pal, vram, oam, rom, ram.
* A memory access that may touch 0x04000000-0x040003FF or OAM but cannot be resolved
  to a single region is a **compile error** (`InterceptError`) listing the PCs.
  `swi` other than 5 (VBlankIntrWait) is a compile error.
* `.data` is copied from the ARM ROM image and `.bss` is zeroed by `GbaDataInit`.
* I/O: DISPCNT, BG0HOFS/BG0VOFS writes and VCOUNT/KEYINPUT reads are shimmed;
  other I/O writes are dropped (listed as warnings). BG0CNT must be a constant.
* OAM writes (constant index) go to a GBA OAM mirror at $D100 (32 objects).
* Palette/VRAM writes go to `HAL_PAL_STORE*` / `HAL_VRAM_STORE*`: 4bpp → 2bpp,
  luminance level `3 - ((R + 2G + B) >> 5)`; OBJ level 0 is clamped to 1 (0 is
  transparent on the DMG). Each write waits for mode 0/1 (strict check: 0 violations).

## 2.2 Shims (`runtime/gb_hal_shims.asm`), memory map in `docs/memory_map.md`
| shim | cost (measured, obj_demo) |
|---|---|
| HAL_KEYINPUT (JOYP → active-low GBA KEYINPUT, L/R always released) | 59 M body, 71 M incl. call/ret/ld |
| HAL_VCOUNT (frame counter via VCOUNT LUT) | ~310 M average |
| VBlankISR (OAM DMA from $D000 via HRAM routine at $FFE0, scroll latch) | 221 M |
| Compose (GBA OAM mirror → shadow OAM via LUTs) | ~6.5k M for 28 sprites |

JOYP mapping: A→A, B→B, Select→Select, Start→Start, D-pad→D-pad, R/L=1 (released).
VBlank wait: `swi 5` and VCOUNT polling loops (`while(VCOUNT>=160); while(VCOUNT<160);`)
both map to the same frame model (a VCOUNT read ≥160 after one <160 = a vsync).

## 2.3 Spatial OAM
`X_gb = floor(x*2/3)+8`, `Y_gb = floor(y*9/10)+16` from page-aligned LUTs in ROM0
(`runtime/hal_luts.inc`, generated by `tools/hal/make_luts.py`), 9-bit X wrap
handled, off-screen/hidden objects skipped, objects split into 8x8 hardware sprites,
at most 40 kept (OAM order = priority).

## Limits
* 8x8 hardware sprites only (8x16 needs a different tile order than GBA 1D mapping).
* OBJ tiles < 256, BG tiles < 128, map: low byte of the tile index only, no flips/palettes.
* Palettes must be written before tiles. Only BG bank 0 / OBJ bank 0 get luminance
  levels; OBJ banks ≠ 0 use the inverted OBP1.
* Backdrop (Phase 3.0): GBA BG palette entry 0 is mapped to its DMG shade L0. GB colour 0
  is reserved for GBA colour index 0; opaque colours of level L are stored as swap(0,L0)(L) and
  BGP undoes the swap. With BG0 off the BG stays on and BGP maps every colour to L0. The palette
  starts as black (GBA reset state). OBJ colours with the backdrop's level are moved one shade
  (3→2, 1→2, 2→3) so sprites stay visible. Limit: changing palette entry 0 after OBJ colours were
  set does not re-shift them (BG colours are recomputed on every BG bank-0 palette write).
* No OBJ-vs-BG priority, no affine, no mode 3/4/5 bitmaps, only BG0.
* L/R are always released (mapping option not implemented).
* Constant OAM indexes only, at most 32 objects mirrored.
* `.data` + `.bss` + stack must fit in the 4 KiB IWRAM window; EWRAM is not mapped.
* BG scroll is passed 1:1 (not scaled).
* The DMG shows at most 10 sprites per line; lines with more are reported (oam_stress: 12).
* Compose is slow for many objects: oam_stress (12×32x32) runs at 300 frames per
  680 vblanks (~26 fps); the logical frame sequence still matches exactly.
* SameBoy / mGBA were not available; the GBA side is a Unicorn reference (`tools/hal/gba_ref.py`)
  with simulated VCOUNT/KEYINPUT and a minimal renderer (no X wrap, all 128 objects).
